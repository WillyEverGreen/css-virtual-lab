Section 1

MD5 Hashing & Collision Analysis

The primary objective of this experiment is to explore the internal architecture of the MD5 (Message-Digest Algorithm 5) cryptographic hash function, understand its block-wise compression pipeline, observe the Strict Avalanche Criterion (SAC), and analyze why MD5 is vulnerable to collision cryptanalysis.

Overview & Scope

Designed by Professor Ronald Rivest in 1991, MD5 computes a deterministic 128-bit (16-byte) hash value represented as a 32-character hexadecimal string from an input of arbitrary bit length. While practically deprecated for digital certificates, MD5 remains an essential pedagogic model for the Merkle-Damgard hash construction.

1. Preprocessing & Padding

Converts arbitrary strings to UTF-8 bytes, appends single 1 bit (0x80), pads to 448 mod 512, and encodes original 64-bit length.

2. 64-Step Compression

Processes 512-bit message blocks through 4 rounds (F, G, H, I) updating state variables A, B, C, D with modular addition and left bit rotations.

3. Strict Avalanche Criterion

Quantifies bit diffusion by demonstrating that flipping a single input bit modifies approximately 50% of the resulting digest bits.

Section 2

Cryptographic Architecture & Mathematical Formulation

MD5 employs a Merkle-Damgard iterated construction. The input message of length L bits is divided into consecutive 512-bit blocks (each consisting of sixteen 32-bit words). An internal 128-bit buffer initialized to fixed constants is updated sequentially by each block through 64 step operations.

1. Initial Buffer State

The algorithm maintains four 32-bit registers (chaining variables) initialized with little-endian hex words:

A = 0x67452301 // 01 23 45 67 (little-endian byte order)
B = 0xEFCDAB89 // 89 AB CD EF
C = 0x98BADCFE // FE DC BA 98
D = 0x10325476 // 76 54 32 10

2. Auxiliary Round Functions

Each of the four rounds applies a distinct non-linear bitwise function that acts as a bit-level scrambler:

Round Steps Auxiliary Function Word Selection index g
Round 1 0 – 15 F(B, C, D) = (B & C) | (~B & D) g = i
Round 2 16 – 31 G(B, C, D) = (B & D) | (C & ~D) g = (5*i + 1) mod 16
Round 3 32 – 47 H(B, C, D) = B ^ C ^ D g = (3*i + 5) mod 16
Round 4 48 – 63 I(B, C, D) = C ^ (B | ~D) g = (7*i) mod 16

3. Per-Step Transformation Formula

At each step i (from 0 to 63), registers are cycled and updated using constant K[i], shift S[i], and message word M[g]:

temp = D
D = C
C = B
B = B + leftRotate((A + auxFunc(B, C, D) + K[i] + M[g]) mod 2^32, S[i])
A = temp

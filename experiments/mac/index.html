Section 1

Message Authentication Code (MAC)

The primary objective of this experiment is to implement, analyze, and verify a Message Authentication Code (MAC) for arbitrary messages using a shared secret key K. Students will explore how MAC provides data integrity and data origin authentication, and observe how an attacker who modifies the message but cannot forge a valid MAC is detected by the receiver.

Core Objective

Understand how symmetric key cryptography solves the fundamental vulnerability of unkeyed hashing: preventing active Man-in-the-Middle attackers from modifying messages and forging valid checksums without knowledge of the secret key K.

1. Data Origin Authentication

Proving that the transmitted payload M was generated by a legitimate sender who holds the shared secret key K.

2. Data Integrity Verification

Detecting any unauthorized modifications, insertions, or payload alterations introduced by an attacker in transit.

3. Tamper Detection

Demonstrating that an attacker who modifies the message but must use a random key to forge a MAC tag will always be detected by the receiver.

Section 2

Cryptographic Theory & Security Comparison

1. What is a Message Authentication Code (MAC)?

A Message Authentication Code (MAC) is a symmetric key cryptographic algorithm that takes an arbitrary-length message payload M and a shared secret key K, and produces a fixed-size authentication tag T:

Tag T = MAC(K, M)

Only parties who possess the secret key K can compute or verify the tag T. If an adversary modifies even 1 bit of M but cannot recompute the MAC (because they don’t have K), the receiver’s verification algorithm detects the tampering.

2. How MAC Works: Sender → Attacker → Receiver Flow

1. Sender Side (Alice)

The sender enters a message M and a secret key K (mutually agreed with the receiver). The MAC algorithm processes both to generate a tag T = MAC(K, M). The sender then transmits M || T (message appended with MAC tag).

2. Attacker (Eve / Man-in-the-Middle)

An attacker intercepts the transmission. They modify the message M to M', but since they don’t know the secret key K, they generate a forged MAC T' using a random key. They forward M' || T' to the receiver.

3. Receiver Side (Bob)

The receiver has the same shared key K. They compute T'' = MAC(K, M') on the received message and compare it with the received tag T'. Since M' ≠ M, the computed T'' ≠ T', and tampering is detected immediately.

3. The HMAC Standard Construction (RFC 2104)

The most prevalent MAC construction is HMAC, defined mathematically as:

HMAC(K, M) = H((K+ ^ opad) || H((K+ ^ ipad) || M))
Where H is the underlying hash (SHA-256), K+ is the zero-padded key,
ipad = 0x36 repeated B times, and opad = 0x5C repeated B times.

4. Cryptographic Mechanism Comparison

Mechanism Key Used Integrity Authentication Non-Repudiation
Unkeyed Hash (SHA-256) None Yes (accidental) No No
MAC (HMAC-SHA256) Symmetric Secret (K) Yes (active MitM) Yes (key holder) No (both hold K)
Digital Signature (RSA) Asymmetric (Private/Public) Yes Yes Yes (signer only)
Section 3

Laboratory Procedure & Process Architecture

The diagram below illustrates the complete cryptographic pipeline of Message Authentication Code (MAC) generation at the sender, transmission across an untrusted network channel, and verification at the receiver:

Step 1

Sender Enters Message & Key

The sender (Alice) enters a plaintext message and a secret key value (mutually agreed with the receiver). The MAC algorithm (HMAC-SHA256) processes both to generate a MAC tag.

Step 2

MAC Appended & Transmitted

The generated MAC tag is appended to the original message. This combined payload M || MAC is transmitted over the channel toward the receiver.

Step 3

Attacker Intercepts & Modifies

An attacker (Eve, if enabled) intercepts the transmission. The attacker modifies the message content but does not know the secret key, so they generate a forged MAC using a random key and forward it with the modified message.

Step 4

Receiver Verifies MAC

The receiver (Bob) uses the same secret key to compute the MAC on the received message. If the computed MAC matches the received MAC, the message is authentic. If it doesn’t match, tampering is detected.

Expected Observations
  • The same key + message always deterministically produces the exact same MAC tag.
  • Even a single character modification in the message completely changes the resulting MAC tag (avalanche effect).
  • When no attacker alters the payload, receiver verification succeeds with 100% confidence.
  • When an adversary tampers with the message, the receiver immediately catches the discrepancy because the attacker cannot compute a valid tag without key K.

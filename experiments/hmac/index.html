Section 1

HMAC Authentication & Verification

The primary objective of this experiment is to explore the mathematical structure and cryptographic guarantees of the HMAC (Keyed-Hash Message Authentication Code) standard (RFC 2104 / FIPS PUB 198-1). Students will inspect the two-pass inner and outer key padding construction, analyze resistance against length-extension attacks, and simulate in-transit packet tampering detection.

Standard Specification & Security Goals

Standardized by Bellare, Canetti, and Krawczyk in 1996, HMAC provides simultaneously data origin authenticity and data integrity without encrypting the message payload. Unlike naive constructions like H(Key || Message) which are vulnerable to length extension attacks on Merkle-Damgard hash functions, HMAC's nested structure guarantees security provided the underlying hash function remains secure.

1. Nested 2-Pass Padding

XORs the zero-padded key K' with inner pad byte 0x36 (ipad) and outer pad byte 0x5C (opad) across 64-byte blocks.

2. Integrity Verification

Recalculates the authentication tag at the receiving end; any single-bit alteration causes complete verification failure.

3. Length Extension Defense

Nesting the hash passes hides the internal Merkle-Damgard state, preventing adversaries from appending forged payloads.

Section 2

Cryptographic Architecture & Mathematical Formulation

HMAC was explicitly designed to operate on top of any iterated cryptographic hash function H (such as SHA-256) using a shared secret key K.

1. The RFC 2104 Mathematical Definition

For a hash function with internal block size B (64 bytes for SHA-256) and output digest length L (32 bytes for SHA-256):

HMAC(K, M) = H( (K' ⊕ opad) || H( (K' ⊕ ipad) || M ) )

Where the variables are defined as follows:

  • K': The normalised key of length B bytes. If len(K) > B, then K' = H(K) appended with zeros to length B. If len(K) < B, zeros are appended to the right of K to reach length B.
  • ipad (Inner Pad): The byte 0x36 repeated B times (e.g. 363636...36 for 64 bytes).
  • opad (Outer Pad): The byte 0x5C repeated B times (e.g. 5c5c5c...5c for 64 bytes).
  • ||: Concatenation of byte arrays.
  • ⊕: Bitwise Exclusive-OR (XOR).

2. Why Naive Concatenation H(K || M) Fails

In iterated hash functions using the Merkle-Damgard construction (such as MD5, SHA-1, and SHA-256), the final digest output is identical to the internal register chaining state after processing the last block. If an application uses Tag = H(K || M):

Length Extension Vulnerability

An attacker who intercepts (M, Tag) can initialize the hash function registers to Tag, append arbitrary padding and malicious data M', and compute a valid signature Tag' = H(K || M || padding || M') without ever knowing the secret key K. HMAC completely eliminates this vulnerability because the outer hash pass H((K' ⊕ opad) || ...) masks the inner chaining state.

3. Encrypt-then-MAC vs MAC-then-Encrypt

When confidentiality and authentication are both required, modern cryptographic best practice mandates Encrypt-then-MAC (EtM): the plaintext is encrypted first with a cipher (like AES-256-CBC), and the HMAC tag is calculated over the resulting ciphertext and initialization vector (IV).

❓ Can an HMAC Digest Be Decrypted Back to the Message?

Learn the fundamental mathematical difference between One-Way Authentication (HMAC) and Two-Way Confidentiality (Encryption/Decryption).

❌ HMAC is Mathematically Non-Reversible (Cannot be Decrypted)

Why HMAC cannot be reversed or decrypted:

  1. Lossy Fixed-Size Compression: The hash function (SHA-256) compresses arbitrary input lengths down to exactly 256 bits. An infinite number of potential inputs map to the same hash (Pigeonhole principle), making one-to-one inversion mathematically impossible.
  2. One-Way Preimage Resistance: SHA-256 employs irreversible non-linear operations (modular addition mod 2^32, circular rotations, and bitwise XORs) across 64 compression rounds.
  3. Confidentiality vs. Integrity: HMAC guarantees Integrity and Authenticity. To achieve Confidentiality (Encryption & Decryption), cryptographic protocols combine HMAC with a symmetric cipher like AES-256 (Encrypt-then-MAC).

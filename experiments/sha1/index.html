Section 1

SHA-1 Secure Hash Algorithm

SHA-1 (Secure Hash Algorithm 1) maps a message of any length to a fixed 160-bit digest, written as 40 hexadecimal characters. Published by NIST in FIPS 180-1, it is built on the Merkle-Damgård construction with a 512-bit compression function.

Experiment Aim

In this experiment you will trace the complete SHA-1 pipeline: message padding to a 512-bit boundary, expansion of 16 message words into 80 scheduled words, four rounds of 20 compression steps each, and the final 160-bit chaining output. You will also measure the Avalanche Effect and understand why SHA-1 is now considered cryptographically broken.

1. Message Padding

Appends a 0x80 byte, zero fill, and the 64-bit big-endian message length so the padded message is always a multiple of 512 bits.

2. 80-Step Compression

Expands each 512-bit block into 80 scheduled words, then processes four rounds of 20 steps updating five 32-bit registers a, b, c, d, e.

3. Avalanche Criterion

A single flipped input bit changes approximately 50% of the 160 output bits, demonstrating strong cryptographic diffusion.

Section 2

Theory & Mathematical Construction

1. Properties of a Cryptographic Hash

A secure hash function H must satisfy five key properties: it must be fast to compute, one-way (preimage resistant), second-preimage resistant (hard to find a second input with the same digest), collision resistant (hard to find any two inputs with the same digest), and exhibit the Avalanche Effect (a small input change causes ~50% output bit change).

Digest Size

160 bits: five 32-bit words. Represented as 40 hexadecimal characters.

Block Size

512 bits: sixteen 32-bit words per compression block. Messages shorter are padded.

Round Structure

4 rounds × 20 steps = 80 compression steps total. Each round uses a distinct logical function and constant K.

2. Step 1: Preprocessing & Padding

Append a single 1 bit (the byte 0x80), then as many 0 bits as needed so that the length is 448 mod 512, then append the original message length in bits as a 64-bit big-endian integer. The padded message is always a multiple of 512 bits.

3. Step 2: Initial Buffer Values (H0 – H4)

Initial Register Constants (H0 – H4): H0 = 0x67452301   H1 = 0xEFCDAB89   H2 = 0x98BADCFE   H3 = 0x10325476   H4 = 0xC3D2E1F0

4. Step 3: 80-Word Message Schedule Expansion

Each 512-bit block is split into W[0] to W[15] (big-endian). The remaining words are expanded as:

80-Word Expansion (for t = 16 to 79): W[t] = ROTL1(W[t-3] ⊕ W[t-8] ⊕ W[t-14] ⊕ W[t-16])

5. Step 4: 80-Step Compression Structure

Initialise a, b, c, d, e with H0 to H4, then for t = 0 to 79:

Compression Transformation (for t = 0 to 79): TEMP = (ROTL5(a) + f(t, b, c, d) + e + K(t) + W[t]) mod 232   e = d   d = c   c = ROTL30(b)   b = a   a = TEMP

6. Step 5: Merkle-Damgard Chaining & Output

After the 80 steps, add a to e into H0 to H4 (mod 232). The next block starts from the updated H values. The final digest is H0 || H1 || H2 || H3 || H4.

7. Security Status & Collision Vulnerabilities

Wang, Yin and Yu (2005) showed collisions in SHA-1 faster than brute force (269 operations). In 2017 the SHAttered attack produced the first practical collision. Modern systems should use SHA-256 or SHA-3 for digital signatures and certificates; SHA-1 survives only in legacy and non-security contexts.
Section 3

Procedure

Follow these experimental steps to observe SHA-1 hashing, padding, message scheduling, and diffusion:

  1. Digest View: Open the Simulation tab. Keep the default input abc and verify the digest equals a9993e364706816aba3e25717850c26c9cd0d89d. Confirm both test vectors pass in the self-check panel.
  2. Custom Input Exploration: Type your own message and watch the digest, input bit count, and block count update in real time. Note how even minor changes produce completely different digests.
  3. Padding Examination: Switch to the Padding view. Note the message bytes, the 0x80 byte, the zero fill, and the 64-bit length. Try messages of 55, 56, and 64 characters to observe when a second block is added.
  4. Message Schedule Tracing: Open the Schedule view. Read W[0] to W[15] taken directly from the block, then the expanded words W[16] to W[79] produced by the ROTL1 expansion formula.
  5. Rounds & Step Inspector: Open the Rounds view. Record the a, b, c, d, e registers at the end of each round. Use the step slider to inspect any single step t with its function f, constant K, and word W[t].
  6. Avalanche Effect Analysis: Open the Avalanche view. Use Flip last bit or edit the modified message. Record the number of changed bits and percentage. Repeat for three different edits and compare to the expected ~80 changed bits (50%) out of 160.

Section 1

SHA-1 Secure Hash Algorithm

SHA-1 (Secure Hash Algorithm 1) maps a message of any length to a fixed 160-bit digest, written as 40 hexadecimal characters. It was published by NIST in FIPS 180-1 and is built on the Merkle-Damgard construction with a 512-bit compression function.

In this experiment you will:

  • Generate SHA-1 digests live for any input message and verify them against known test vectors.
  • Follow the RFC 3174 padding rule: the 0x80 byte, zero fill, and the 64-bit big-endian length.
  • Observe the expansion of a 512-bit block into 80 words and the 80 compression steps in four rounds.
  • Measure the avalanche effect by flipping a single bit of the input and counting the changed digest bits.
  • Understand why SHA-1 is now considered cryptographically broken for collision resistance.
Section 2

Theory

Properties of a cryptographic hash

A hash function H should be fast to compute, one-way (preimage resistant), hard to make a second input with the same digest (second-preimage resistant), and hard to find any two inputs with the same digest (collision resistant). A small change in the input should change about half of the output bits (the avalanche effect).

Parameters

  • Digest size: 160 bits (five 32-bit words).
  • Block size: 512 bits (sixteen 32-bit words).
  • Message limit: less than 2^64 bits.
  • Rounds: 4 rounds of 20 steps each, 80 steps in total.

Step 1: Padding

Append a single 1 bit (the byte 0x80), then as many 0 bits as needed so that the length is 448 mod 512, then append the original message length in bits as a 64-bit big-endian integer. The padded message is always a multiple of 512 bits.

Step 3: Message schedule

Each 512-bit block is split into W[0] to W[15] (big-endian). The remaining words are:

W[t] = ROTL1( W[t-3] XOR W[t-8] XOR W[t-14] XOR W[t-16] ),  16 <= t <= 79

Step 4: Compression (80 steps)

Initialise a, b, c, d, e with H0 to H4, then for t = 0 to 79:

TEMP = ROTL5(a) + f(t, b, c, d) + e + K(t) + W[t]   (mod 2^32)

Step 5: Chaining

After the 80 steps, add a to e into H0 to H4 (mod 2^32). The next block starts from the updated H values. The final digest is H0 || H1 || H2 || H3 || H4.

Security status

Wang, Yin and Yu (2005) showed collisions in SHA-1 faster than brute force (2^69 operations). In 2017 the SHAttered attack produced the first practical collision. Modern systems should use SHA-256 or SHA-3 for digital signatures and certificates; SHA-1 survives only in legacy and non-security uses.

Section 3

Procedure

  1. Open the Simulation tab. In the Digest view, keep the default input abc and check that the digest equals a9993e364706816aba3e25717850c26c9cd0d89d. The self-check panel should show both test vectors as passed.
  2. Type your own message and watch the digest, input bit count and block count update at once.
  3. Switch to the Padding view. Note the message bytes, the 0x80 byte, the zero fill and the 64-bit length. Try a message of 55, 56 and 64 characters and observe when a second block is added.
  4. Open the Schedule view and read W[0] to W[15] taken from the block, then the expanded words W[16] to W[79].
  5. Open the Rounds view. Record the a, b, c, d, e registers at the end of each round and use the step slider to inspect any single step t, with its function f, constant K and word W[t].
  6. Open the Avalanche view. Use Flip last bit or edit the modified message, and record the number of changed bits and the percentage. Repeat for three different edits.
  7. Compare your observations with the expected value of about 80 changed bits out of 160 (50 percent).
